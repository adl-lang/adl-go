# Walking ADL values in Go with generated visitors

The `govisitor` sub-task of `goadlc` writes a `<pkg>_visitor.go` beside
every `<pkg>.go` that the `gotypes` sub-task writes. For every ADL struct,
union and newtype you get a set of `Visit<Type>` interfaces to implement
and an `Accept` method that dispatches to whichever of those your visitor
provides and otherwise walks the fields for you.

A visitor is any Go value. You implement `Visit<Type>` methods only for the
types you care about, pick a payload type `P` that flows down the value and
a result type `R` that flows back up, and call `Accept` on the root.

The machinery is the generic-methods flavour of the visitor that
`ohm-cli generate go --generic-methods` produces for an Ohm grammar, applied
to ADL declarations instead of grammar rules. If you have built an ADL AST
from a parse tree with that toolchain (the `samples/goohm` module and
`docs/grammar2ast.md` in the sheafdb repository), this is the second half:
the ohm visitor builds the ADL values, and the ADL visitor walks them.

2. [Configuration](#2-configuration): the `GoVisitor` block of the cfg and every parameter.

4. [The eight visitor interfaces and `Accept`](#4-the-eight-visitor-interfaces-and-accept).
5. [`DefaultAccept` and the `Accept<Field>` helpers](#5-defaultaccept-and-the-acceptfield-helpers): the per-field-type rules.
6. [Unions](#6-unions).

The snippets use this ADL module:

```adl
module tree {
struct Atom      { String name; Bool quoted; };
struct Hierachy  { Atom node; Vector<Node> kids; };
union  Node      { Atom atom; Hierachy hierachy; Word64 index; Void none; };
struct Axis      { Vector<Node> nodes; Nullable<Atom> anchor; StringMap<Atom> named; };
};
```

which `gotypes` renders, in package `tree`, as `type Atom struct { _Atom }`
over `_Atom{ Name string; Quoted bool }`, `type Hierachy struct { _Hierachy }`
over `_Hierachy{ Node Atom; Kids []Node }`, `type Axis struct { _Axis }` over
`_Axis{ Nodes []Node; Anchor *Atom; Named map[string]Atom }`, and
`type Node struct { Branch NodeBranch }` with one branch struct per
alternative: `_Node_Atom{ V Atom }`, `_Node_Hierachy{ V Hierachy }`,
`_Node_Index{ V uint64 }`, `_Node_None{ V struct{} }`.

## 1. Where it sits

`goadlc` runs its sub-tasks in sequence: `GoTypes` first, then `GoVisitor`,
then any `GoApis`. For each ADL module in its set the visitor sub-task
writes one file:

```
tree.adl --(goadlc GoTypes)-----> <Outputdir>/tree/tree.go, tree_ast.go    the types
tree.adl --(goadlc GoVisitor)---> <Outputdir>/tree/tree_visitor.go         Visitor*_X, Accept, DefaultAccept, Accept<Field>
```

The visitor file is written into the **same package** as the types file.
`Accept` is a method on the generated struct, and Go only allows a type's
methods to be declared in the package that defines the type, so there is no
way to put the visitor machinery in a package of its own. That is also why
`GoVisitor.Outputdir` must equal `GoTypes.Outputdir` (section 2): the two
files have to land in the same directory.

The file carries the standard goadlc header (`// Code generated by goadlc -
DO NOT EDIT.`) and imports only what its body used:

| import | when |
|---|---|
| `<GoAdlPath>/visit` | always, unless `SkipTypeCheckMethod` is set |
| `slices`, `maps` | when some `StringMap` field is descended (section 5) |

A reference to a type in another generated module needs no extra import:
`node.Field.Accept[P, R](...)` is a method call on a value whose type the
types file already imported.

A module in which nothing is generated (only type aliases, or only the
leaf declarations of section 3) gets no visitor file at all.

## 2. Configuration

`goadlc` is driven by a JSON config file: `goadlc -cfg <file>`, or `go tool
github.com/adl-lang/adl-go/goadlc -cfg <file>` from a module that lists
goadlc as a tool dependency. The file is a JSON encoding of
`cli.gengo.GenGo`. Visitors are switched on by adding a `GoVisitor` block
next to `GoTypes`. This is `visitor_tests/cfgs/visitor.cfg.json`, the config
that generates the test module in this repository:

```json
{
  "Loader": {
    "Searchdir": ["adl"],
    "MergeAdlext": "adl-go",
    "BundleMaps": [
      {
        "AdlModuleNamePrefix": "sys",
        "GoModPath": "github.com/adl-lang/adl-go/adl",
        "AdlSrc": "file://../goadlc/adl/stdlib_go"
      }
    ],
    "Files": ["adl/**/*.adl"]
  },
  "Mod": { "Outputdir": "." },
  "GoTypes": {
    "GoAdlPath": "github.com/adl-lang/adl-go/adl",
    "Outputdir": "generated"
  },
  "GoVisitor": {
    "GoAdlPath": "github.com/adl-lang/adl-go/adl",
    "Modules": [],
    "SkipTypeCheckMethod": false,
    "Outputdir": "generated"
  }
}
```

(Outside this repository the `sys` bundle's `AdlSrc` is normally
`"file://$ADLSTDLIB"`, which goadlc resolves by running
`adlc show --adlstdlib`.) Relative paths in the file, including both
`Outputdir`s, are resolved against the directory goadlc is run from, which
is also where it looks for the `go.mod` that fixes the generated import
paths. `visitor_tests/Taskfile.local.yml` runs it that way:

```sh
cd visitor_tests
go run ../goadlc/main.go -cfg ./cfgs/visitor.cfg.json   # task visitor_tests:gen
go test ./...                                           # task visitor_tests:test
```

and the root `task gen` and `task test` include both.

`GoVisitor` defaults to `null`, so a config without the block generates no
visitors and is unaffected by this sub-task. The block's fields are the
`cli.govisitor.GoVisitor` struct
(`goadlc/adl/goadlc/cli/govisitor.adl`):

| field | default | meaning |
|---|---|---|
| `Outputdir` | required | Directory the generated files go under, relative to the config's working directory, with one sub-directory per ADL module (`generated/tree/tree_visitor.go` for module `tree`, `generated/a/b/b_visitor.go` for module `a.b`). **Must be the same as `GoTypes.Outputdir`** (section 1); goadlc does not check this, since `GoTypes` may be absent when only the visitors are regenerated. |
| `Modules` | `[]` | The ADL module names (`"tree"`, `"a.b"`) to generate visitors for. Empty means every module the `Loader` was asked to load through `Files`. Naming a module that was not loaded is an error; that includes modules that arrive through a `BundleMap`, such as `sys.types`, which are never generated for. |
| `GoAdlPath` | `"github.com/adl-lang/adl-go/adl"` | Import path of the Go ADL runtime. The visitor runtime is imported from `<GoAdlPath>/visit`. Set it only if you vendor or fork the runtime; it should match `GoTypes.GoAdlPath`. |
| `SkipTypeCheckMethod` | `false` | Omit the `visit.TypeCheckMethod` call from every generated `Accept` (section 8). The `visit` import is then omitted too. |
| `NoGoFmt` | `false` | Do not run `go/format` over the generated file. |

### The `Modules` set decides what is descended

The set of modules that get visitors is also what decides, for every
field, whether the walk goes *into* the field's value or treats it as a
leaf. A field whose type refers to a struct or union in a module **in the
set** is descended: its `Accept<Field>` calls the field value's `Accept`.
A field whose type refers to a declaration in a module **outside the set**
(a bundle module such as `sys.types`, or one of your own modules you left
out) is a leaf, exactly as a `String` is, and the walk does not go into it.

Generation is per module, so module `a`'s visitor file is written without
knowing whether module `b`'s was. The `Modules` set is what keeps the two
consistent: if `a` descends into a type from `b`, `b` must be in the set so
that the `Accept` being called exists. The simplest arrangement is the
default, every loaded module.

## 3. What is generated, by declaration kind

| ADL declaration | generated |
|---|---|
| `struct` | 8 interfaces, `Accept`, `DefaultAccept`, one `Accept<Field>` per field (section 5) |
| `union` | 8 interfaces, `Accept`, `DefaultAccept` with a branch type switch (section 6) |
| `newtype` | 8 interfaces, `Accept`, `DefaultAccept` descending into the underlying value (section 7.2) |
| generic `struct<T>`, `union<T>`, `newtype X<T>` | as the non-generic case, with the declaration's type parameters prepended to the interfaces' (section 7.1) |
| `type` alias | nothing; the alias is expanded wherever it appears |
| `newtype` whose Go type cannot carry methods: a pointer (`Nullable<...>`), an interface (`Json`) or a bare type parameter (`newtype B<T> = T`), directly or through further aliases and newtypes | nothing; a leaf |
| declaration with a `go_custom_type` annotation | nothing; a leaf |

"Leaf" means nothing is generated for the declaration, and a field whose
type refers to it is visited the way a primitive is (section 5): the walk
stops there and the visitor is not told about it.

A type alias is expanded before any of this is decided, so a field declared
`type Name = String; struct S { Name n; }` is a `String` field, and one
declared through an alias of a struct is a struct reference.

## 4. The eight visitor interfaces and `Accept`

For every generated struct or union `X` the visitor file declares eight
interfaces. Each has one method, `VisitX`, and the letters in the interface
name say what that method takes and returns: `P` a payload argument, `R` a
result, `E` an error. `X` is the Go type name, the same identifier the
types file used.

| Interface | Method |
|---|---|
| `Visitor_X[P, R any]` | `VisitX(node *X)` |
| `VisitorE_X[P, R any]` | `VisitX(node *X) error` |
| `VisitorP_X[P, R any]` | `VisitX(node *X, payload P)` |
| `VisitorPE_X[P, R any]` | `VisitX(node *X, payload P) error` |
| `VisitorR_X[P, R any]` | `VisitX(node *X) (result R)` |
| `VisitorRE_X[P, R any]` | `VisitX(node *X) (result R, err error)` |
| `VisitorPR_X[P, R any]` | `VisitX(node *X, payload P) (result R)` |
| `VisitorPRE_X[P, R any]` | `VisitX(node *X, payload P) (result R, err error)` |

The interfaces carry `[P, R any]` even where the method does not mention
one of them (`Visitor_X` mentions neither). That keeps all eight uniform,
and it is what lets the assertion block in section 9 record one `(P, R)`
per type.

Every `X` gets an `Accept` with the shape below. The node parameter is a
plain `*X`; `P` and `R` are type parameters of the method:

```go
func (node *Atom) Accept[P, R any](visitor any, payload P) (result R, err error) {
	if v, ok := visitor.(Visitor_Atom[P, R]); ok {
		v.VisitAtom(node)
		return
	}
	if v, ok := visitor.(VisitorE_Atom[P, R]); ok {
		err = v.VisitAtom(node)
		return
	}
	// ... P, PE, R, RE, PR, PRE in that order
	visit.TypeCheckMethod[P, R](visitor, "Atom", node)
	return node.DefaultAccept[P, R](visitor, payload)
}
```

- `visitor` is `any`. A visitor needs no base type and no registration; it
  is matched purely by type assertion against the eight interfaces, in the
  table order, and the first `VisitAtom` that fits is called. Since a Go
  type can have only one method of that name, at most one fits.
- If none fits, `visit.TypeCheckMethod` runs (section 8) and then
  `DefaultAccept` walks the fields (section 5).
- The payload `P` is passed unchanged from `Accept` to `DefaultAccept` to
  each `Accept<Field>` and on into the child's `Accept`; it flows down the
  call stack. `R` and `error` are returned at every level; they flow up.
  Both are carried in Go's own call stack, so a visitor holds no state
  unless it wants to.
- `Accept` has a pointer receiver. Call it on a pointer or on an
  addressable value (`axis.Accept[...]` where `axis` is a variable is
  fine; a `Make_Axis(...)` call result is not).
- A `nil` visitor matches no interface and is skipped by
  `TypeCheckMethod`, so it falls through to `DefaultAccept` at every node:
  a full walk that calls nothing.

Compared with the ohm-go visitor there is no `this` argument and no
`AssertName`: an ADL value carries no parse-tree node to check against.

## 5. `DefaultAccept` and the `Accept<Field>` helpers

### `DefaultAccept`

`DefaultAccept` calls the helper of each **descended** field (one whose
value the walk goes into, see the table below) in declaration order and
stops at the first error. Leaf fields keep their `Accept<Field>` helper but
`DefaultAccept` does not call it. The result it returns is the **last
descended field's** result:

```go
func (node *Hierachy) DefaultAccept[P, R any](visitor any, payload P) (result R, err error) {
	if result, err = node.AcceptNode[P, R](visitor, payload); err != nil {
		return
	}
	if result, err = node.AcceptKids[P, R](visitor, payload); err != nil {
		return
	}
	return
}

func (node *Atom) DefaultAccept[P, R any](visitor any, payload P) (result R, err error) {
	return
}
```

"Last descended field" matters when you rely on the default walk for a
type and read its result. For `struct Labelled { Point at; String text; }`
the result is `at`'s, since `text` is a leaf and never called. If the last
descended field is a `Vector`, the result is its last element's; if it is a
`Nullable` that is nil, or a `Vector` or `StringMap` that is empty, it is
the zero `R`; and if it is a reference whose own `DefaultAccept` descends
nothing (an `Atom`, say, with no `VisitAtom` in play) it is the zero `R`
whatever the earlier fields produced. A visitor that wants anything other
than that implements `VisitX` and combines the field results itself
(section 9). A struct with no fields, or none descended, gets a
`DefaultAccept` that just returns.

### `Accept<Field>`

Each field gets one helper, named `Accept` plus the field's Go name (the
ADL field name with its first letter upper-cased, as in the types file).
What the helper does depends on the field's type expression after type
aliases are expanded:

| field type | `Accept<Field>` body |
|---|---|
| a primitive other than the three containers below (`String`, `Int32`, `Bool`, `Word64`, `ByteVector`, ...), `Void`, `Json`, `TypeToken<T>`, a type parameter, or a reference to a leaf declaration (section 3) | `// leaf: <type>` then `return`. The visitor is not called; `result` is the zero `R`. |
| `Vector`, `Nullable` or `StringMap` whose element is, at any depth, a leaf (`Vector<String>`, `Nullable<Vector<T>>`, `StringMap<sys.types.Pair<Int64, Int64>>`) | a leaf too: `// leaf: Vector<String>` then `return`, never an empty loop |
| reference to a struct, union or newtype in the generated set | `return node.Field.Accept[P, R](visitor, payload)` |
| `Vector<T>` | `for i := range node.Field { <visit node.Field[i] as T> }` then `return` |
| `Nullable<T>` | `if node.Field != nil { <visit node.Field as T> }` then `return`; Go dereferences the pointer at the method call |
| `StringMap<T>` | `for _, k := range slices.Sorted(maps.Keys(node.Field)) { v := node.Field[k]; <visit v as T> }` then `return` |

The leaf comment names the field's ADL type after alias expansion, with
references fully scoped (`// leaf: sys.types.Pair<Int64, Int64>`), so a
glance at the helper says why nothing is visited.

`<visit expr as T>` is recursive. For a descended reference it is
`if result, err = expr.Accept[P, R](visitor, payload); err != nil { return }`;
for a nested `Vector`, `Nullable` or `StringMap` it is the loop or `if`
above again, with a fresh variable name (`i`, `i2`, ...; `k`, `k2`, ...;
`v`, `v2`, ...), so `Vector<Vector<Atom>>` becomes
`for i := range node.F { for i2 := range node.F[i] { node.F[i][i2].Accept... } }`
and `Vector<Nullable<Atom>>` becomes
`for i := range node.F { if node.F[i] != nil { node.F[i].Accept... } }`.
Classification runs bottom-up, which is what makes a container of leaves a
leaf: `Vector<Nullable<String>>` is a leaf, `Vector<Nullable<Atom>>` is a
descended vector of nullables. The helpers for `Axis` look like this:

```go
func (node *Axis) AcceptNodes[P, R any](visitor any, payload P) (result R, err error) {
	for i := range node.Nodes {
		if result, err = node.Nodes[i].Accept[P, R](visitor, payload); err != nil {
			return
		}
	}
	return
}

func (node *Axis) AcceptAnchor[P, R any](visitor any, payload P) (result R, err error) {
	if node.Anchor != nil {
		if result, err = node.Anchor.Accept[P, R](visitor, payload); err != nil {
			return
		}
	}
	return
}

func (node *Axis) AcceptNamed[P, R any](visitor any, payload P) (result R, err error) {
	for _, k := range slices.Sorted(maps.Keys(node.Named)) {
		v := node.Named[k]
		if result, err = v.Accept[P, R](visitor, payload); err != nil {
			return
		}
	}
	return
}
```

Two details of the container rules are deliberate and worth knowing:

- **Vector elements are reached by index**, `node.Nodes[i]`, not by a
  range value. `Accept` has a pointer receiver, and `node.Nodes[i]` is
  addressable, so the `*Node` your `VisitNode` receives points at the real
  element in the slice. A visitor that mutates the node it is handed
  mutates the value being walked.
- **`StringMap` elements are copied.** A map element is not addressable in
  Go, so the generated code copies it into `v` and calls `Accept` on the
  copy. Your `Visit` method therefore sees a `*Atom` that points at a
  temporary: a mutating visitor's changes to a `StringMap` element are
  lost, and if you need to update map elements you must write them back
  yourself (`node.Named[k] = updated`) from a `VisitAxis` of your own.
  Keys are visited in sorted order so that walks are deterministic across
  runs; Go's own map iteration order is not.

Both rules apply at every nesting level, so the element of a
`Vector<StringMap<Atom>>` is a copy and the element of a
`StringMap<Vector<Atom>>` is reached through the copied slice header,
which still aliases the same backing array.

A reference to a struct in another module of the generated set is
descended exactly like a reference within the module.

## 6. Unions

A union gets the same eight interfaces and the same `Accept` as a struct.
Its `DefaultAccept` switches on the branch and descends into the branch
value with the same rules as a struct field:

```go
func (node *Node) DefaultAccept[P, R any](visitor any, payload P) (result R, err error) {
	switch b := node.Branch.(type) {
	case _Node_Atom:
		return b.V.Accept[P, R](visitor, payload)
	case _Node_Hierachy:
		return b.V.Accept[P, R](visitor, payload)
	case _Node_Index:
		// leaf: Word64
		return
	case _Node_None:
		// leaf: Void
		return
	}
	panic("unhandled branch in : Node")
}
```

The branch types are the `_<Union>_<Branch>` structs the types file
declares. A branch whose value is a `Vector`, `Nullable` or `StringMap`
uses the same recursive `<visit b.V as T>` as a struct field, followed by
`return`. When no branch is descended the switch binds nothing
(`switch node.Branch.(type)`), because Go rejects a type-switch binding
that no case uses.

There are **no per-branch `Visit` interfaces**. In the ohm-go visitor each
named case of a rule gets its own struct and `Visit` method; here the
branch value is already a typed node with its own `Visit<Type>`
(`VisitAtom`, `VisitHierachy`), which plays that role. A leaf branch
(`index`, `none`) is not reported to the visitor at all by the default
walk; a visitor that wants to see it implements `VisitNode` and
inspects the union itself (`node.Cast_index()`), as the printer in
section 10 does.

## 7. Generics and newtypes

### 7.1 Generic declarations

For `struct Pair<A, B>`, which `gotypes` renders as `Pair[A, B any]`, the
declaration's type parameters are prepended to the interfaces' own, and
every method's receiver is the instantiated type:

```go
type Visitor_Pair[A, B, P, R any] interface {
	VisitPair(node *Pair[A, B])
}

func (node *Pair[A, B]) Accept[P, R any](visitor any, payload P) (result R, err error)
func (node *Pair[A, B]) DefaultAccept[P, R any](visitor any, payload P) (result R, err error)
func (node *Pair[A, B]) AcceptA[P, R any](visitor any, payload P) (result R, err error)
```

A `TypeParamConstraintList` annotation on the declaration is carried into
the interfaces as `gotypes` carries it into the type:
`Visitor_Keyed[K comparable, P any, R any]` for
`@adlc.config.go_.TypeParamConstraintList ["comparable"] struct Keyed<K>`.

A field whose type is a type parameter is a leaf (`// leaf: T`), and so is
any container of one (`// leaf: Vector<T>`, `// leaf: Nullable<T>`). This
holds **even when the value is instantiated with a visitable type**: for
`struct Box<T> { T item; Vector<T> items; Atom tag; }` a `Box<Atom>` has
its `tag` visited and its `item` and `items` skipped, because `Box`'s
methods are generated once for every `T` and know nothing of `Atom`. Only
the fields whose type is a concrete reference, or a container of one, are
descended. If you need the `T` values walked, visit them from your
`VisitBox`.

A field referencing a generic declaration with concrete arguments
(`Box<Atom> b;`) is descended with the usual
`node.B.Accept[P, R](visitor, payload)`, and so is `Box<T> inner;` inside
another generic declaration, where Go resolves the instantiation.

A generic union's branch cases name the branch type with the type
parameters that branch mentions, as `gotypes` declares them:

```go
func (node *Opt[T]) DefaultAccept[P, R any](visitor any, payload P) (result R, err error) {
	switch b := node.Branch.(type) {
	case _Opt_Some[T]:
		// leaf: T
		return
	case _Opt_None:
		// leaf: Void
		return
	case _Opt_Xs:
		for i := range b.V {
			if result, err = b.V[i].Accept[P, R](visitor, payload); err != nil {
				return
			}
		}
		return
	}
	panic("unhandled branch in : Opt")
}
```

If a declaration's own type parameter is called `P` or `R`, the visitor's
payload and result parameters are renamed `P2` and `R2` (then `P3`, ...),
and the declaration's keep their names:

```go
type VisitorPRE_Weird[P, R, P2, R2 any] interface {
	VisitWeird(node *Weird[P, R], payload P2) (result R2, err error)
}

func (node *Weird[P, R]) Accept[P2, R2 any](visitor any, payload P2) (result R2, err error)
```

A Go type has one method of a given name, so **a visitor type can handle
one instantiation of a generic declaration**: one `VisitBox`, say for
`*Box[Atom]`. When the walk meets a `Box[string]`, none of that
instantiation's eight interfaces match, and `TypeCheckMethod` (section 8),
which is handed the node, sees that the `VisitBox` it found takes another
instantiation of the same declaration and does not panic. The
`Box[string]` falls through to `DefaultAccept`, so its `tag` is still
visited but no `VisitBox` is called for it. A `VisitBox` for `*Box[Atom]`
with the wrong `P` or `R` still panics when a `Box[Atom]` is walked. To
handle several instantiations, use several visitor types.

### 7.2 Newtypes

A newtype gets the eight interfaces and the `Accept` of a struct, named
after the newtype (`Visitor_Path`, `VisitPath(node *Path)`), and a
`DefaultAccept` that visits the underlying value, `*node`, with the section
5 rules. There are three shapes:

```adl
newtype Path = Vector<Atom>;   // type Path []Atom
newtype Wrapped = Atom;        // type Wrapped Atom
newtype Id = String;           // type Id string
```

A container is walked over the dereferenced receiver:

```go
func (node *Path) DefaultAccept[P, R any](visitor any, payload P) (result R, err error) {
	for i := range *node {
		if result, err = (*node)[i].Accept[P, R](visitor, payload); err != nil {
			return
		}
	}
	return
}
```

(`StringMap` likewise, with `slices.Sorted(maps.Keys(*node))` and
`v := (*node)[k]`.)

A newtype over a generated declaration is a distinct Go type with none of
the original's methods, so `DefaultAccept` converts the receiver to the
underlying type and calls its `Accept`. The conversion is spelled with the
same Go type the types file used, so for `newtype Wrapped = Atom;` with
`Atom` imported from module `tree` the visitor file imports `tree` too (in
the same module it would read `(*Atom)(node)`):

```go
func (node *Wrapped) DefaultAccept[P, R any](visitor any, payload P) (result R, err error) {
	return (*tree.Atom)(node).Accept[P, R](visitor, payload)
}
```

A newtype over such a newtype (`newtype Rewrapped = Wrapped;`) converts to
`*Wrapped`, which converts again. So `VisitWrapped` and then `VisitAtom`
both see the one value, each through its own type.

A newtype over a leaf is a leaf default:

```go
func (node *Id) DefaultAccept[P, R any](visitor any, payload P) (result R, err error) {
	// leaf: String
	return
}
```

`VisitId` is still offered, so a visitor can act on an `Id` where it could
not on a `String`.

Generic newtypes follow the generic rules: `newtype Ids<T> = Vector<T>;`
has the receiver `*Ids[T]`, interfaces `[T, P, R any]`, and a leaf
`DefaultAccept` (`// leaf: Vector<T>`), whatever `T` it is instantiated
with; `newtype Boxed<T> = Box<T>;` converts to `(*Box[T])(node)`.

A newtype stays a leaf (nothing generated; a field of it is
`// leaf: nt.MaybeAtom`, with the module name) when:

- it has a `go_custom_type` annotation, or
- its Go type cannot have methods: Go rejects a method whose receiver base
  type is a pointer, an interface or a type parameter, which is what
  `gotypes` renders for `newtype MaybeAtom = Nullable<Atom>;`
  (`type MaybeAtom *Atom`), `newtype J = Json;` (`type J any`) and
  `newtype B<T> = T;` (`type B[T any] T`). The check follows aliases and
  newtypes, so `newtype MaybeMaybe = MaybeAtom;` is a leaf too.

A field referencing a newtype, or a generic declaration, in the generated
set is descended with `node.Field.Accept[P, R](...)` like any other
reference; a container of such a field is walked. References to
declarations outside the set (`sys.types.Maybe<Atom>`,
`sys.types.Pair<Atom, Atom>`) remain leaves, whatever their arguments.

## 8. `visit.TypeCheckMethod`

The most common mistake while writing a visitor is to declare `VisitAtom`
with a `P` or `R` that differs from the ones the caller instantiated. No
interface then matches and the method would be silently skipped, with the
default walk running in its place. The runtime package
`github.com/adl-lang/adl-go/adl/visit` guards against that:

```go
package visit

// TypeCheckMethod panics if v has a method named "Visit"+typeName whose
// signature matches none of the eight generated interfaces for P and R.
// node is the value being accepted (a *X, or *X[A, B] for a generic
// decl). A nil v, or one implementing SkipCheckName, is not checked.
func TypeCheckMethod[P, R any](v any, typeName string, node any)

// SkipCheckName opts a visitor type out of TypeCheckMethod.
type SkipCheckName interface{ SkipCheckName() }
```

Every generated `Accept` calls
`visit.TypeCheckMethod[P, R](visitor, "X", node)` just before falling
through to `DefaultAccept`. It uses reflection (`MethodByName`) to look for
a method named `VisitX`. If one exists, none of the eight interfaces
matched it for this `P` and `R`, and it panics with the expected shapes
(spelled with the node's Go type), the received signature and the likely
call site. This is the panic for a `VisitAtom(node *tree.Atom, env Env)
(string, error)` met by a walk instantiated at `[Env, int]`:

```
VisitAtom: found a method by name, but its signature matches none of the Visitor*_Atom[main.Env, int] interfaces.
  expected one of
    VisitAtom(node *tree.Atom)
    VisitAtom(node *tree.Atom) error
    VisitAtom(node *tree.Atom, payload main.Env)
    VisitAtom(node *tree.Atom, payload main.Env) error
    VisitAtom(node *tree.Atom) (result int)
    VisitAtom(node *tree.Atom) (result int, err error)
    VisitAtom(node *tree.Atom, payload main.Env) (result int)
    VisitAtom(node *tree.Atom, payload main.Env) (result int, err error)
  received
    func(*main.evaluator, *tree.Atom, main.Env) (string, error)
  for the likely call site see
    /path/to/eval.go:23
  Implement visit.SkipCheckName on the visitor to disable this check.
```

A `TypeCheckMethod` panic means a `P`/`R` mismatch in your code, not a bad
input; input problems come back as `error` values.

The one `VisitX` by name that does not panic is a method for another
instantiation of a generic declaration: a `VisitBox(node *Box[Atom], ...)`
found while a `*Box[string]` is being accepted is left alone and the value
falls through to `DefaultAccept` (section 7.1). The node is what lets the
check tell the two apart.

Successful checks are cached per (visitor type, node type, `P`, `R`), so
the reflection cost is paid once per combination. A mismatch is never
cached and panics every time. There are two ways to opt out:

- Per visitor: implement the marker interface `visit.SkipCheckName` (a
  method `SkipCheckName()`) on the visitor type. A `nil` visitor is also
  skipped.
- Per generated package: set `SkipTypeCheckMethod: true` in the cfg
  (section 2), which omits the call and the `visit` import from the
  generated file. The reason to do so is binary size: `MethodByName`
  keeps every `Visit*` method alive through dead-code elimination.

## 9. Writing a visitor

### The entry point

There is no root helper. An ADL value is already a typed Go value, so the
walk starts with `Accept` on whichever node you hold:

```go
func Print(axis *tree.Axis) (string, error) {
	return axis.Accept[any, string](&printer{}, nil)
}
```

### One visitor, one `R` per type

The visitor is usually an empty struct, or one holding only the state it
accumulates. Each `Visit` method fixes `R` to whatever its type should
produce, and because dispatch is by interface the same struct satisfies
`VisitorRE_Atom[any, string]` and, say, `VisitorRE_Axis[any, []string]` at
the same time. Write the choices down as a compile-time block; it doubles
as the table of `R` per type:

```go
type printer struct{}

var (
	_ tree.VisitorRE_Atom[any, string]     = (*printer)(nil)
	_ tree.VisitorRE_Hierachy[any, string] = (*printer)(nil)
	_ tree.VisitorRE_Axis[any, string]     = (*printer)(nil)
	// ... one line per Visit method
)
```

Use the `P` variants when a parent has context to push down; use the `E`
variants and return errors rather than panicking, since `Accept` carries
them up for you.

### Let `DefaultAccept` do the pass-through

A type whose result is simply its last descended field's result, or whose
fields you only want walked for their side effects, needs no `Visit`
method:
`DefaultAccept` forwards the same `P` and `R` into every field. That
includes unions: a `Node` whose branches all produce the same `R`
needs no `VisitNode`, because the branch switch forwards to `VisitAtom`
or `VisitHierachy` with the same type arguments.

### Same-`R` children: call the generated helper

When a child should produce the same `R` as its parent, call the
generated `Accept<Field>` helper, spelling out the type arguments:

```go
func (p *printer) VisitHierachy(node *tree.Hierachy) (string, error) {
	var (
		head string
		err  error
	)
	if head, err = node.AcceptNode[any, string](p, nil); err != nil {
		return "", err
	}
	// ...
}
```

### Different-`R` children, and collecting container results: call the child's `Accept`

The `Accept<Field>` helpers and `DefaultAccept` always forward the
parent's `P` and `R`, and a container helper returns only its last
element's result. Whenever a child must produce something else, or you
want every element's result rather than the last, reach the child value
through the struct's field and call its `Accept` with the type arguments
you want:

```go
func (p *printer) kids(nodes []tree.Node) ([]string, error) {
	var (
		out []string
		s   string
		err error
	)
	for i := range nodes {
		if s, err = nodes[i].Accept[any, string](p, nil); err != nil {
			return nil, err
		}
		out = append(out, s)
	}
	return out, nil
}
```

Index the slice rather than ranging over values, for the reason in
section 5: `Accept` wants a pointer to the real element. For a
`StringMap` field, copy the element into a local first and iterate the
sorted keys, as the generated helper does.

Unlike the ohm-go visitor there is nothing to build: the child is a field
of the value you already hold, so there is no struct literal to copy from
the generated helper.

### `[P, R]` at every instantiation

In this flavour the type arguments must be written at every call:
`node.AcceptNode[any, string](p, nil)`, `nodes[i].Accept[int, int](c, depth)`.
Go could infer `P` from the `payload` argument, but `R` appears only in
the results, and type arguments can only be omitted from the end of the
list, so both are spelled out. The upside is that a node is just data and
`(P, R)` is chosen per call: the same `*tree.Axis` can be handed to a
printer instantiated at `[any, string]` and then to a counter at
`[int, int]`, with nothing rebuilt or cast. An instantiated method such as
`node.AcceptNodes[any, string]` is an ordinary method value and can be
passed around as a `func`.

## 10. Worked example: a printer and a counter

Two visitors over the `tree` module from the top of this document, sharing
one set of nodes. The printer renders a value as text with `P = any` and
`R = string`; the counter counts atoms with a depth payload, `P = int`,
and a count result, `R = int`, and records the deepest atom it saw. The
output shown in the comments is what the program prints against the code
goadlc generates for that module. A longer example in the same style, over
the sheafdb `tree.adl` with its `Ref`, `Seq` and `Path` types, is
`visitor_tests/m2/m2_test.go` (`printer` and `counter`), and
`visitor_tests/m1` and `m3` do the same for the struct and the generics and
newtype shapes.

```go
package main

import (
	"fmt"
	"maps"
	"slices"
	"strings"

	"example.com/generated/tree"
)

// printer: any in, string out.

type printer struct{}

var (
	_ tree.VisitorRE_Atom[any, string]     = (*printer)(nil)
	_ tree.VisitorRE_Hierachy[any, string] = (*printer)(nil)
	_ tree.VisitorRE_Node[any, string]     = (*printer)(nil)
	_ tree.VisitorRE_Axis[any, string]     = (*printer)(nil)
)

func (p *printer) VisitAtom(node *tree.Atom) (string, error) {
	if node.Quoted {
		return "'" + node.Name + "'", nil
	}
	return node.Name, nil
}

func (p *printer) VisitHierachy(node *tree.Hierachy) (string, error) {
	var (
		head string
		kids []string
		err  error
	)
	if head, err = node.AcceptNode[any, string](p, nil); err != nil {
		return "", err
	}
	if kids, err = p.list(node.Kids); err != nil {
		return "", err
	}
	return head + ": [" + strings.Join(kids, ", ") + "]", nil
}

// VisitNode handles the two leaf branches, which the default walk would
// render as the zero string, and lets DefaultAccept forward the rest.
func (p *printer) VisitNode(node *tree.Node) (string, error) {
	var (
		idx uint64
		ok  bool
	)
	if idx, ok = node.Cast_index(); ok {
		return fmt.Sprintf("#%d", idx), nil
	}
	if _, ok = node.Cast_none(); ok {
		return "none", nil
	}
	return node.DefaultAccept[any, string](p, nil)
}

func (p *printer) VisitAxis(node *tree.Axis) (string, error) {
	var (
		parts []string
		s     string
		err   error
	)
	if parts, err = p.list(node.Nodes); err != nil {
		return "", err
	}
	if s, err = node.AcceptAnchor[any, string](p, nil); err != nil {
		return "", err
	}
	if node.Anchor != nil {
		parts = append(parts, "@"+s)
	}
	for _, k := range slices.Sorted(maps.Keys(node.Named)) {
		v := node.Named[k]
		if s, err = v.Accept[any, string](p, nil); err != nil {
			return "", err
		}
		parts = append(parts, k+"="+s)
	}
	return strings.Join(parts, ", "), nil
}

func (p *printer) list(nodes []tree.Node) ([]string, error) {
	var (
		out []string
		s   string
		err error
	)
	for i := range nodes {
		if s, err = nodes[i].Accept[any, string](p, nil); err != nil {
			return nil, err
		}
		out = append(out, s)
	}
	return out, nil
}

// counter: depth in, atom count out.

type counter struct {
	maxDepth int
}

var (
	_ tree.VisitorPR_Atom[int, int]      = (*counter)(nil)
	_ tree.VisitorPRE_Hierachy[int, int] = (*counter)(nil)
	_ tree.VisitorPRE_Axis[int, int]     = (*counter)(nil)
)

func (c *counter) VisitAtom(node *tree.Atom, depth int) int {
	c.maxDepth = max(c.maxDepth, depth)
	return 1
}

func (c *counter) VisitHierachy(node *tree.Hierachy, depth int) (int, error) {
	var (
		n, kids int
		err     error
	)
	if n, err = node.AcceptNode[int, int](c, depth); err != nil {
		return 0, err
	}
	if kids, err = c.sum(node.Kids, depth+1); err != nil {
		return 0, err
	}
	return n + kids, nil
}

// No VisitNode: the generated Node.DefaultAccept forwards atom and
// hierachy branches with the same [int, int], and returns 0 for the
// index and none leaves, which is the count we want for them.

func (c *counter) VisitAxis(node *tree.Axis, depth int) (int, error) {
	var (
		total, n int
		err      error
	)
	if total, err = c.sum(node.Nodes, depth); err != nil {
		return 0, err
	}
	// Anchor holds at most one Atom, so the helper's "last result" is
	// exactly its count: 1 if present, 0 if nil.
	if n, err = node.AcceptAnchor[int, int](c, depth); err != nil {
		return 0, err
	}
	total += n
	for _, k := range slices.Sorted(maps.Keys(node.Named)) {
		v := node.Named[k]
		if n, err = v.Accept[int, int](c, depth); err != nil {
			return 0, err
		}
		total += n
	}
	return total, nil
}

func (c *counter) sum(nodes []tree.Node, depth int) (int, error) {
	var (
		total, n int
		err      error
	)
	for i := range nodes {
		if n, err = nodes[i].Accept[int, int](c, depth); err != nil {
			return 0, err
		}
		total += n
	}
	return total, nil
}

func main() {
	var (
		axis = tree.Make_Axis(
			[]tree.Node{
				tree.Make_Node_hierachy(tree.Make_Hierachy(
					tree.Make_Atom("A", false),
					[]tree.Node{
						tree.Make_Node_atom(tree.Make_Atom("B", false)),
						tree.Make_Node_index(3),
					},
				)),
				tree.Make_Node_none(),
			},
			nil,
			map[string]tree.Atom{
				"x": tree.Make_Atom("7", true),
			},
		)
		c     = &counter{}
		text  string
		count int
		err   error
	)
	if text, err = axis.Accept[any, string](&printer{}, nil); err != nil {
		panic(err)
	}
	fmt.Println(text) // A: [B, #3], none, x='7'
	if count, err = axis.Accept[int, int](c, 0); err != nil {
		panic(err)
	}
	fmt.Println(count, c.maxDepth) // 3 1
}
```

Points to notice:

- The same `axis` value is walked twice with different type arguments.
  Nothing is rebuilt between the two calls.
- The printer and the counter make opposite choices about `Node`. The
  printer wants text for the leaf branches, so it implements `VisitNode`,
  handles those itself and calls `DefaultAccept` for the others. The
  counter is happy with the zero `R` for a leaf, so it has no `VisitNode`
  at all.
- Both visitors loop over `Kids` and `Named` themselves rather than
  calling `AcceptKids` or `AcceptNamed`, because they need every
  element's result, not the last. Both do call `AcceptAnchor`, where
  "last result" and "only result" coincide.
- The counter's `VisitAtom` uses the `PR` shape (payload, result, no
  error) while its other methods use `PRE`. The shape is chosen per
  method; only the `(P, R)` pair has to agree across a walk.

## 11. Go versions

The generated visitor file uses methods with their own type parameters
(`func (node *Atom) Accept[P, R any](...)`), which Go added in 1.27. A
module that **consumes** generated visitors therefore needs

```
go 1.27
```

or later in its `go.mod`. With an older `go` directive the file fails to
compile with an error about type parameters on a method.

`goadlc` itself, and the `adl` runtime module that provides `adl/visit`,
stay at go 1.26: the generator only emits text, and `visit.TypeCheckMethod`
is a generic function, not a generic method. In a `go.work` workspace the
workspace `go` line must be at least 1.27 for the consuming module to be
built, which is why this repository's `go.work` says `go 1.27.1` while
`goadlc/go.mod` and `adl/go.mod` say `go 1.26.4`.

The ohm-go visitor generator offers a second, struct-generics flavour that
works on older Go; `govisitor` does not. ADL values are built by
`Make_` constructors and decoded from JSON long before any visitor is
chosen, so tying each value to one `(P, R)` for life, as struct generics
would, is not an option here.
